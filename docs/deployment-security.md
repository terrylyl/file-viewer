# Deployment Security

`index.html` is self-contained and includes a Content Security Policy (CSP) meta tag generated by `npm run build`. Its policy has three important properties:

- `connect-src 'none'` blocks fetch, WebSocket and other outbound page connections.
- `script-src` authorizes only the exact hashed application script produced by that build; there is no `unsafe-inline` script exception.
- `worker-src blob:` permits the app's generated parsing/query Workers while rejecting external Worker URLs.

For static hosting, preserve the generated CSP meta tag exactly. If the hosting platform also emits a `Content-Security-Policy` HTTP header, copy the policy value from the generated meta tag into that header, or make the header at least as restrictive while retaining the generated script hash and `worker-src blob:`. Do not set a second divergent policy: browsers enforce every delivered policy.

`frame-ancestors` is effective only when sent as an HTTP header, so deployments that must prevent framing should add the generated policy as a response header. Test the deployed page after every build because the application script hash changes whenever its source changes.
